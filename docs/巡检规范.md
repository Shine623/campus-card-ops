# 一卡通系统巡检规范

## 一、巡检频率

| 频率 | 时间 | 执行人 | 内容 |
|---|---|---|---|
| 每日 | 08:00 | 值班运维 | 自动脚本 + 人工确认 |
| 每周 | 周一 10:00 | 运维负责人 | 周度深度巡检 |
| 每月 | 1 日 | 运维负责人 | 月度全面巡检 |
| 学期初 | 开学前 1 周 | 全员 | 专项检查（应对高并发） |

## 二、每日巡检（自动）

执行 `scripts/daily_check.sh`，cron 配置：

```bash
0 8 * * * /opt/scripts/daily_check.sh >> /var/log/cardcheck/cron.log 2>&1
```

### 检查项

| 类别 | 检查项 | 阈值 | 处置 |
|---|---|---|---|
| 系统 | CPU 使用率 | >80% 警告 | 查进程，找占用高的 |
| 系统 | 内存使用率 | >85% 警告 | 查是否有泄漏 |
| 系统 | 磁盘使用率 | >85% 错误 | 清理日志或扩容 |
| 系统 | 负载 | >核数 警告 | 查进程 |
| 数据库 | 连接数 | >200 警告 | 查是否有泄漏 |
| 数据库 | 主从延迟 | >10s 警告 | 查大事务 |
| 数据库 | 慢查询数 | >100 警告 | 分析慢查询 |
| 应用 | 进程存活 | 挂掉即错误 | 立即重启 |
| 应用 | 端口监听 | 未监听即警告 | 检查配置 |
| 业务 | 交易失败率 | >1% 错误 | 查失败原因 |
| 业务 | PENDING 充值 | >0 错误 | 手工补单 |
| 对账 | 余额差异 | 有差异即错误 | 运行完整对账 |

### 人工确认项

脚本跑完后，值班人员需要：

1. 看报告状态（✅ / ⚠️ / ❌）
2. ⚠️ 的项记录到值班日志，观察是否持续
3. ❌ 的项立即处理，处理不了的上报
4. 回复"已巡检"到运维群

## 三、每周巡检

### 1. 日志检查

```bash
# 检查是否有异常错误
grep -i "error\|exception" /var/log/tomcat/catalina.out | grep -v "已知问题" | tail -50
```

### 2. 数据库健康

```sql
-- 表空间使用
SELECT table_name, ROUND(data_length/1024/1024, 2) AS data_mb,
       ROUND(index_length/1024/1024, 2) AS index_mb
FROM information_schema.tables
WHERE table_schema='card'
ORDER BY data_length DESC LIMIT 10;

-- 检查是否有锁等待
SELECT * FROM information_schema.innodb_trx
WHERE trx_state='LOCK WAIT';
```

### 3. 备份验证

```bash
# 确认最近 7 天备份都存在
ls -lh /backup/card/ | tail -10

# 随机抽一个备份验证可恢复（在测试库）
mysql -h test-db -u root -p < /backup/card/card_20260615.sql
```

### 4. 慢查询分析

```bash
mysql -u root -p < sql/top_slow.sql
```

关注：`scan_ratio > 100` 的 SQL（全表扫描），考虑加索引。

## 四、每月巡检

### 1. 容量规划

| 项 | 当前 | 增长 | 预计何时需要扩容 |
|---|---|---|---|
| 数据库大小 | 【】 | 【】/月 | 【】 |
| 日志占用 | 【】 | 【】/月 | 【】 |
| 交易量 | 【】 | 【】/月 | 【】 |

### 2. 账号权限审计

```sql
SELECT user, host FROM mysql.user;
SHOW GRANTS FOR 'card'@'%';
```

检查：
- 是否有离职人员的账号
- 是否有权限过大的账号
- 是否有空密码账号

### 3. 安全补丁

- 检查系统安全更新
- 检查 MySQL 版本是否有已知漏洞
- 检查 Tomcat 版本

### 4. 文档更新

- 更新架构图（如有变更）
- 更新常见问题手册（补充新问题）
- 更新联系人清单

## 五、学期初专项检查

开学前 1 周，做以下专项检查（应对充值高峰）：

| 检查项 | 标准 | 备注 |
|---|---|---|
| 数据库连接池 | 至少 500 | 平时 200 够用，高峰期不够 |
| 应用实例数 | 至少 3 台 | 单台扛不住 |
| 充值网关 TPS | 压测 > 200/s | 开学首日峰值约 150/s |
| 磁盘空间 | > 50% 可用 | 日志会暴涨 |
| 监控告警 | 全部验证一次 | 确保能收到告警 |
| 应急预案 | 演练一次 | 特别是回滚流程 |

## 七、升级与变更

任何变更（版本升级、配置修改）必须：

1. **提前 3 天** 在运维群公告
2. **避开** 业务高峰（11:30-13:00、17:00-18:30）
3. **灰度** 发布，先 1 台观察 30 分钟
4. **准备回滚** 方案
5. **记录** 变更日志
